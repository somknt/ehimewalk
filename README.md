# えひめウォーククエスト

> 歩く楽しさが、健康と愛媛の未来をつくる。

AI × 健康増進 × 観光活性化 × ゲーミフィケーションのウォーキングアプリです。「えひめAI地域課題解決コンテスト」に向けて開発しています。

歩数でコインを貯めてキャラクターを着せ替え、AI が提案する散策クエストで愛媛県内の観光スポットを訪れると、地域限定アイテムがもらえます。

## 現在の状態

Web アプリとして動きます（Vercel で公開）。AWS には未接続で、データはブラウザ内のモック API（端末の localStorage）に保存します。AI の提案は、登録スポットから規則で選ぶモックです（画面に「モック」と表示）。進み具合は [tasks.md](.kiro/specs/ehime-walk-quest/tasks.md) を参照してください。

## 動く機能

画面上の通貨は「コイン」と表示します（仕様書・コード内の「ポイント（pt）」と同じものです）。

- **キャラクター作成**（`/welcome`）：初回だけ。名前・髪型・髪色・肌色・目の色・最初の服
- **歩数計測**：スマートフォンの動きのセンサーで歩数を数えます。アプリを開くと自動で計測を始め、ホームの「歩数の計測」カードで止める・はじめるを切り替えられます。iPhone は初回に「動作と方向」の許可を求めます
  - アプリを閉じている間・画面が消えている間は数えられません（Web アプリの制限）。HealthKit / Health Connect 連携（アプリ版）で対応予定です
  - センサーの歩数は推定値として扱い、不正防止の確認ができるまで正式ランキングには入れません
- **コイン**：100 歩 = 1 コイン（1 日の上限なし）。同じ歩数を何度同期しても二重に付与しません。1 日 1 回のログインボーナス（+10）
- **ホーム**：左右スワイプで 2 ページ。キャラクター・今日の歩数・所持コイン・ログインボーナス／おすすめクエスト・健康ミッション・健康ダッシュボード
- **ガチャ**（`/gacha`）：1 回 50 コイン。排出確率 N60% / R30% / SR9% / SSR1%。持っているアイテムが出たらレア度に応じたコインに変換
- **着せ替え**（`/gacha/wardrobe`）：場所ごとに所持アイテムを装備・解除
- **冒険**（`/adventure`）：スポット一覧、観光マップ（OpenStreetMap）、AI 散策クエスト（出発地点・時間・興味・ペース）、愛媛冒険図鑑
- **スポット詳細**（`/adventure/spots/:spotId`）：GPS チェックイン（初回だけ限定アイテム）、AI 観光ガイド（登録した情報だけを表示）、情報源
- **フレンド**（`/friends`、下部メニューのランキングの左）：自分のフレンドコードのコピー・共有、フレンドコードで探して申請、届いた申請の承認・見送り、送った申請の取り消し、フレンドの解除、応援。いまの相手は架空のサンプルユーザーで、申請すると数秒後に承認されます（モック）
- **ランキング**：全ユーザー・愛媛県・フレンドの 3 タブ（いまは架空のサンプルユーザー）
- **マイページ**：名前・見た目・目標の変更、称号、歩数履歴、訪問履歴、利用の記録、設定、発表用デモ、データ削除

### デモ操作と発表用デモ

公開版でも使えます。デモで追加した歩数とコインは記録上区別し、正式ランキングには入れません。

- **デモ操作**（ホーム）：コインを +100 / +500 / +1,000、今日の歩数を +100 / +1,000 / +5,000 / +10,000 歩
- **発表用デモ**（マイページ）：「デモ用データで始める」で、キャラクター作成済み・過去 7 日分の歩数・コイン・アイテム・訪問済みスポット 1 か所がある状態にします。「発表で見せる順番」から各画面へ移動できます。終わったら「すべてのデータを削除する」で最初の状態に戻ります

### ホーム画面に追加（PWA）

- iPhone：Safari で開き、共有ボタン →「ホーム画面に追加」
- Android：Chrome のメニュー →「アプリをインストール」（または「ホーム画面に追加」）

アイコン付きで、アドレス欄の無い全画面で開きます。

## 開発環境で動かす

Node.js 22.22 以上が必要です。

```powershell
cd frontend
npm install
npm run dev
```

表示された URL（通常は http://localhost:5173 ）をブラウザで開きます。歩数のセンサーは HTTPS か localhost でしか使えないため、スマートフォンで試すときは公開版（Vercel）を使ってください。

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバーを起動 |
| `npm run build` | 型チェックと本番ビルド |
| `npm run lint` | oxlint による静的解析 |
| `npm test` | Vitest による単体テスト |

### 公開（Vercel）

`main` に push すると自動で公開されます。設定はリポジトリ直下の `vercel.json`（`frontend` をビルドして `frontend/dist` を配信、どの URL でも `index.html` を返す）にあります。

### モックについて

- データはブラウザの localStorage に保存します（ゲームのデータは `ewq.mock.v1`、センサーの歩数は `ewq.motion.v1`）。マイページの「すべてのデータを削除する」で消えます
- 保存データが壊れていても起動します。壊れた項目は初期値に戻し、読めないデータは `ewq.mock.v1.broken` に退避します
- URL に `?mockError` を付けると、通信エラー時の表示を確認できます
- 歩数の取得元は `src/api/stepProviders/` の `StepDataProvider` で差し替えられます（Web は `DeviceMotionStepProvider`）

## フォルダ構成

```
.kiro/specs/ehime-walk-quest/  要件・設計・タスク
docs/                          根拠資料、フェーズ2 の設計
frontend/                      React + TypeScript + Vite + Tailwind CSS
  public/                      アイコン、PWA のマニフェスト
  src/api/                     API インターフェースとモック実装（歩数の取得元は stepProviders/）
  src/domain/                  ゲーム規則（コイン・ガチャ・日付・チェックイン・ミッション・称号・クエスト）
  src/data/                    スポット・アイテムのマスタ
  src/features/                画面の部品（歩数計・地図・ガチャ・クエストなど）
  src/pages/                   画面
vercel.json                    Vercel の公開設定
```

## セキュリティ

AWS の認証情報や API キーはコミットしないでください。`VITE_` で始まる環境変数は公開ファイルに埋め込まれるため、秘密情報には使えません（Bedrock のキーはサーバー側で扱います）。
